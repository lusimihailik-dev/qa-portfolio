# День 3 — Git

### Что такое Git
- Система контроля версий
- Хранит историю, позволяет откатываться
- Нужен QA для работы в команде и портфолио

### Команды
- git init — создать репозиторий
- git status — состояние файлов
- git add файл — добавить в индекс
- git commit -m "сообщение" — зафиксировать
- git log / git log --oneline — история
- git diff — что изменилось
- git config --global user.name/email — настройка

### Ветки
- git branch — список / создать
- git checkout -b имя — создать и перейти
- git switch имя — переключиться
- git merge имя — слить в текущую
- git branch -d имя — удалить

### Удалённый репозиторий
- git clone URL — склонировать
- git remote -v — список remote
- git pull — забрать
- git push — отправить


### Что такое коммит
- Снимок состояния файлов в определённый момент
- У каждого коммита: хеш, автор, дата, сообщение
- Коммиты образуют историю — можно вернуться к любой точке

### Понятия
- Репозиторий — папка под контролем Git
- Индекс (staging) — что войдёт в следующий коммит
- Commit — снимок
- HEAD — указатель на текущий коммит

### Связь с правами (День 2)
- Файл без x нельзя выполнить
- cat, nano, less не требуют x
- Git-репозиторий работает в текущей папке и вверх по дереву


### Отмена изменений в Git
- git restore file — откатить изменения в файле (не в индексе)
- git restore --staged file — убрать из индекса, оставить изменения
- git reset HEAD~1 — отменить последний коммит, изменения останутся
- git reset --hard HEAD~1 — отменить коммит и изменения (ОПАСНО)
- git checkout -- file — старый способ отката файла

### Правило безопасности
- git restore и git reset --hard не спрашивают подтверждения
- Корзины в Git нет
- Перед откатом: git status + git diff — убедись, что делаешь


### Полный цикл изменения файла в Git
1. git status — увидеть, что изменилось
2. git diff — посмотреть точную разницу
3. git add файл — добавить в индекс
4. git commit -m "..." — зафиксировать
5. git status — проверить: working tree clean

### Разбор git diff
- + строка добавлена
- - строка удалена
- без знака — без изменений
- @@ -1,2 +1,3 @@ — было 2 строки, стало 3

### Полезное
- git sta<Tab> — автодополнение команд
- git diff HEAD~1 HEAD — разница между коммитами
- Сообщение коммита: «что изменилось», а не «что делала»
- Всегда git diff перед git add — привычка QA

### Что было непонятно
- Git работает только внутри папки с .git
- Проверка: git status покажет fatal, если не в репозитории
- ~/файл — это попытка ВЫПОЛНИТЬ файл, а не открыть
- Чтобы посмотреть: cat файл, less файл, nano файл
- Чтобы выполнить: нужен x в правах и это должна быть программа
