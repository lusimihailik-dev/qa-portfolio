## Безопасность API

### Найденные баги
- BUG-03: пароли в открытом виде (исправлено: bcrypt, API не отдаёт пароль)
- BUG-04: email и пароль в URL (GET), список пользователей без авторизации

### Почему GET с паролем — плохо
- URL сохраняется в истории браузера, логах сервера, кэше
- Даже HTTPS не спасает — данные остаются в логах
- OWASP: чувствительные данные не должны быть в query string

### Почему список пользователей без авторизации — плохо
- OWASP API3:2023 — Excessive Data Exposure
- Любой может получить email и id всех пользователей

### Что должно быть
- Логин через POST, данные в теле
- /api/users требует токен
- Пароль не возвращается (уже сделано)

### BUG-03 исправлен

### Что сделано
- Установлен bcrypt в контейнере api
- Пароли в БД хранятся в виде bcrypt-хешей
- API не возвращает пароль (только id, email, name)
- Логин проверяет через bcrypt.checkpw

### Проверка
- curl http://10.191.30.183:3000/users?email=user@example.com&password=Password123 → JSON без пароля
- curl http://10.191.30.68/api/users?email=user@example.com&password=Password123 → JSON через nginx
- Оба пользователя (user и admin) проходят проверку
- Пароль в ответе отсутствует

### BUG-05 (побочный)
- После хеширования логин сломался ([])
- Причина: хеши в БД не соответствовали паролям
- Решение: пересоздать хеши через bcrypt.hashpw
