# День 4 — Теория QA: виды и уровни

## QA vs QC vs Testing
- QA — обеспечение качества, предотвращение багов
- QC — контроль качества, проверка продукта
- Testing — конкретные действия по поиску багов

## Функциональное vs нефункциональное
- Функциональное: ЧТО делает система
- Нефункциональное: КАК делает (скорость, безопасность, удобство)

## Уровни тестирования
- Модульное — разработчик, отдельная функция
- Интеграционное — модули вместе
- Системное — вся система
- Приёмочное — заказчик

## Виды тестирования
- Дымовое — основное работает?
- Регрессионное — новое не сломало старое
- Санитарное — узкая проверка фикса
- Исследовательское — без тест-кейсов
- Приёмочное — перед релизом
- Позитивное / негативное

## Ящики
- Чёрный — QA
- Белый — разработчик
- Серый — частично

## Упражнение 1. Функциональное vs нефункциональное

### Функциональное (что делает)
1. Логин и пароль → вход в личный кабинет
2. Поиск товара → товар найден
3. Корзина → видим товар и сумму

### Нефункциональное (как делает)
1. Скорость загрузки страниц (производительность)
2. Валидность SSL-сертификата (безопасность)
3. Нагрузка 1000 пользователей (нагрузка)
4. Совместимость с браузерами (совместимость)
5. Удобство интерфейса (юзабилити)

## Упражнение 2. Уровни на примере qa-base

### Модульное
1. chmod 600 test.txt → права стали rw-------
2. touch file.txt → создан пустой файл
3. echo "текст" >> README.md → строка дозаписана

### Интеграционное
1. touch + chmod → файл создан и права изменены
2. apt update + apt upgrade → список обновлён и пакеты обновлены
3. git add + git commit → файл в индексе и зафиксирован

### Системное
1. apt install curl → curl -I https://example.com → статус 200
2. sleep 100 & → ps aux | grep sleep → kill %1 → jobs (пусто)
3. git init → echo > file → git add → git commit → git log (видим коммит)

## Упражнение 3. Дымовое vs регрессионное

### Дымовое для интернет-магазина
1. Сайт открывается
2. Логин работает
3. Каталог отображается
4. Корзина открывается
5. Оформление заказа доступно

### Регрессионное после добавления кнопки «Поделиться»
1. Вёрстка карточки товара не сломалась
2. Другие кнопки (Купить, В корзину) работают
3. Корзина считает сумму
4. Страница товара открывается
5. Мобильная версия корректна

## Упражнение 4. Позитивное vs негативное (регистрация)

### Позитивные
1. Валидный email + пароль 8+ символов + имя → регистрация успешна
2. Email с поддоменом (user@mail.co.uk) → принят
3. Пароль со спецсимволами (P@ssw0rd!) → принят

### Негативные
1. Пустой email → ошибка «Введите email»
2. Email без @ → ошибка «Некорректный email»
3. Пароль короче 8 символов → ошибка «Пароль слишком короткий»
4. Занятый email → ошибка «Email уже используется»
5. Пробелы в имени → ошибка «Недопустимые символы»

## Тестирование сценариев с почтой
- Нельзя использовать реальную почту
- Используют Mailtrap.io, temp-mail.org, MailHog
- Проверяют: тему, отправителя, текст, ссылку, срок действия
- Ссылка должна быть одноразовой
- Нельзя раскрывать, что email не найден
